## 关键瓶颈

### 1. HK SSH 不通
当前 SSH 到 HK 被拒绝（端口开但连接被 close），只能通过 AgentBus 发消息给 CC-HK。
**影响**：无法远程运维 HK 服务器，无法直接部署代码。
**解决**：需要 Tank 物理检查或者通过 VNC 控制台修复 sshd/fail2ban。

### 2. CC agents 不能自己醒来
所有 CC agent 都是被动唤醒（wake 脚本查 bus inbox），不能自主启动。
**影响**：任务延迟大（最快也要等下一个 cron tick），agent 没有持续思考能力。
**解决方向**：拉长 CC session（保持常驻），或者把高频任务改为 Hermes cron 直接执行。

### 3. 两套 AgentBus 实例
本地 localhost:7700 和 HK 43.132.211.23:7700 是独立 DB，不互通。
**影响**：消息可能丢失（已修复 wake 脚本路由，但本地实例还在跑旧数据）。
**解决**：统一只用 HK 实例，停掉本地实例。或者做 DB 同步。

### 4. Token 成本不透明
CC agents 走智谱 API，成本不透明。不知道每天花了多少。
**影响**：无法做成本优化。
**解决**：各 agent 日报加"今日 token 用量"字段。

## 成长路径

### 对我（Echo）的要求
1. **更好的裁判**：不只看"做了没"，要看"做得怎么样"
2. **更好的规划**：提前一周想好各 agent 的工作方向，不当天拍脑袋
3. **更好的沟通**：任务描述清晰、可执行，不含歧义
4. **持续进化**：每次犯错的根因分析写进经验系统

### 对 CC agents 的要求
1. **主动性**：不只是完成派发的任务，要自己发现问题
2. **质量意识**：完成任务后自检，不要交半成品
3. **透明性**：遇到困难及时报告，不要硬扛到超时
4. **学习**：每次任务总结经验，下次做得更好

### 协作原则
- **Echo 不微观管理**：给方向，不规定每一步怎么做
- **Agent 自主执行**：选择自己的方法，对结果负责
- **结构化汇报**：日报/周报按格式来，Echo 审查有标准
- **安全第一**：任何有风险的操作（删除、部署到生产）必须先报 Echo 确认
